# 局內成長與經濟規格

最後核對：2026-10-24。本文描述已實作的玩法，作為戰利品、手動合成、法則商店、回響等級與重骰的共同規格。
操作入口見 [README](README.md)，模組分工與接手注意事項見 [PROJECT_CONTEXT](PROJECT_CONTEXT.md)。

本文的原始碼路徑、頁面與指令皆以專案根目錄為準。

## 1. 節點與成長循環

| 場景 | 已實作的用途 |
|---|---|
| 一般／菁英／BOSS 戰鬥 | 勝利依鎖定階級獲得金幣及 0～3 個角色選項，BOSS 不衰減 |
| 整備 | 搬移、交換、手動合成、販賣角色與裝備極式 |
| 商店角色分頁 | 購買角色；兩排我方隊伍同時可見 |
| 商店法則分頁 | 選定一名自有角色，購買法則並直接裝備 |
| 營地 | 抵達時自動免費提升一級回響等級並消耗，影響後續角色抽選 |

每場戰鬥全員滿血開始，受傷與死亡不帶到下一場；營地不補血。
遊戲進度只存在目前頁面的記憶體，重新整理或離開頁面會失去；沒有續玩存檔。

### 地圖操作與一次性格位

- 正式旅程與工坊預覽均點擊相鄰格直接前進，沒有「前往此格」第二步。方向鍵可選取，Enter／空白鍵前進；不可達或崩塌格只顯示資料。
- 正式旅程保留約 0.48 秒鏡頭平移，動畫中忽略連點；事件與待領獎勵完成前不可繼續移動。
- 商店抵達時自動開啟，關閉（含 Escape）即消耗；營地抵達即自動升級並消耗。完成格使用完成符號與底色，仍可通行，不會再次交易或升級。
- 平手不發金幣或角色獎勵，但可查看統計；目前終點平手也結束旅程，屬沿用消耗規則的暫定處理。
- 戰鬥結束先停留於勝敗演出：勝利顯示 VICTORY，點擊後才結算並開啟戰利品；非勝利顯示 GAME SET。敗北點擊後直接返回地圖的戰鬥前一格，撤回進入戰鬥那一步的步數及路徑，若該步造成前格脆弱地板崩塌也還原。敵人格未消耗，可重新走入挑戰；已揭露／訪問紀錄、原敵隊及鎖定獎勵保留。平手仍消耗事件，點擊後可查看統計並返回地圖，不敗退。
- 脆弱地板沒有事件彈窗或獎勵，通行照常計入衰減回合。首次踏入時可站立，成功離開後崩塌；無效移動不會破壞它。崩塌格仍顯示為洞與叉號，但不能再進入。
- 崩塌記錄為探索狀態的 `collapsed` Set，不改寫原地圖；重置探索恢復。規則可能封住回頭路，不會自動修復或改換路線。
- `rules.quotas.fragile` 設定脆弱地板數量，支援 0。新地圖按大小縮放（半徑 4 預設 6，空地由 21 減為 15）；舊自訂配額缺少或無效此欄位補 0 並列出紀錄，以免破壞原有配額。

### 戰利品階級衰減

獎勵衰減取代舊探索警戒，敵人 HP 不再隨探索增加。設定存於地圖 rewardDecay：{enabled,stages:[{after,tier}]}，初始為全階級，after 表示距上一階段再經過幾回合；每列 1～999 回合、最多 10 列，可增刪，階級只能維持或下降。空階段陣列保留全獎勵。預設啟用，階段為 3→高、再 2→中、再 1→低、再 2→無，累積門檻為第 3／5／6／8 回合。

| 階級 | 金幣比例 | 角色獎勵 |
|---|---:|---|
| 全 | 100% | 3 選 1 |
| 高 | 80% | 2 選 1 |
| 中 | 50% | 1 選 1 |
| 低 | 20% | 無 |
| 無 | 0% | 無 |

只有普通敵人與菁英從首次實際揭露時開始計時；工坊全圖檢視不算揭露。成功移動一格計一回合，包含回訪、商店、營地及脆弱地板；無效移動、原地整備、領獎與戰鬥時間不計。新揭露當下為第 0 回合，進入敵人格的那一步也計回合，隨即鎖定階級；整備、敗北重試不再改變該格獎勵。BOSS 一律全獎勵。金幣為 floor(該類戰鬥基礎金幣 × 階級比例 / 100)，角色只改選項數，不改角色星等或回響抽選規則。低階級只確認金幣，不開角色視窗；無階級不開領獎視窗、直接完成結算。零獎勵格仍須戰鬥通過。

地圖格標示階級與金錢比例；滑鼠移入或鍵盤聚焦時，頂部提示當前角色選項數、距離下一階段的回合數及其金錢／角色幅度。工坊亦提供預覽。首次揭露回合與獎勵鎖定僅存在本局記憶體，不回寫編輯設定。

### 隱藏玩家等級與敵隊適配

公開版接上D1後，菁英／BOSS先依 [歷史勝利隊伍規格](PLAYER_TEAMS_SPEC.md) 讀取相容玩家紀錄；其BOSS也會按適配等級匹配。下段的原敵隊適配規則繼續用於一般戰，以及網路／歷史資料不可用時的編輯器敵隊備援。只有勝利才上傳開戰快照，紀錄等級為該戰升級前的playerLevel。

新旅程有隱藏 playerLevel，從 1 起算；每場有效勝利結算加 1（包含無戰利品與 BOSS），敗北／平手／重複 token 不增加，不因領獎或整備變動。新旅程重設，不在玩家 UI 顯示。敵隊 matchLevel 預設 1，允許 1～1000000 整數；缺少／型別錯誤／超界時逐欄補 1 並列出紀錄，備份保留。首次進入普通或菁英戰鬥時，先按分類排除權重 0 與空隊，再選適配等級與玩家等級差距最小者；上下同距離取較低等級，僅在該等級內依出現權重抽選。BOSS 完全不依玩家等級，僅按原權重。各格敵隊抽出後存於 enemyRolls，整備／戰敗重試不重新匹配；只選既有敵隊，不自動調整角色能力。編輯器左側可搜尋名稱及精確適配等級，兩條件交集；填等級時排除 BOSS，清空顯示全部，搜尋不清除表單草稿。BOSS 的適配欄位停用。

### 菁英／BOSS 敵方極式

菁英與終點 BOSS 啟用敵方自己的極式，使用自動模式，冷卻到且可施放便直接施放；一般敵方不施放。使用極式與極式結算後的被動皆只監聽被動持有者所屬陣營。敵方圓框顯示於「敵方」標牌右側分隔線區，滑鼠停留可查看說明。敵隊由編輯器以 skillId 指定，舊檔預設 null，不自動分配。完整資料、陣營事件與 UI 見 [戰鬥規格](BATTLE_SPEC.md)。

## 2. 隊伍、身分與共用資料

- 出戰 `active` 與儲存 `reserve` 各十格。多格角色只放起始錨點，後續佔位存 `null`，但不可當成空位。
- `id` 指角色資料庫定義，`instanceId` 指本局獨立角色。同角色可重複持有，操作目標以實例區分。
- 整備與商店共用隊伍、金幣、法則及技能；角色資料庫模板不因本局操作改寫。
- 種族與階級固定能力增減各套用一次，起始星數即生效；升星不重複累加，合成或裝法則由原始角色快照重算。
- 本局使用編輯設定的快照；編輯器不即時更改進行中的旅程。調整資料後請重新開始遊戲驗證。
- 買賣、領取、合成或交換失敗，不能部分提交金幣、庫存、角色或法則變更。

新旅程會自動裝備技能庫中第一個符合初始出戰隊伍條件的極式；沒有符合者維持未裝備。後續整備仍只卸下失效技能，不自動改裝。

## 3. 戰利品與角色三選一

終點 BOSS 勝利的正式 UI 在 VICTORY 點擊確認並完成一次結算後，直接返回 index.html，不開終點戰利品視窗；下列領獎流程適用一般與菁英。純旅程引擎保留原結算資料，但目前沒有續玩存檔。

### 結算與待領狀態

1. 只接受目前戰鬥 token 對應的合法結算。
2. 勝利發放一次金幣、完成事件格，依鎖定階級抽取並保存 0～3 個角色選項。
3. 開啟戰利品入口，金錢與角色兩項皆須完成，並非二選一。金錢小彈窗只確認已入帳金額，不再次加錢；角色視窗選一隻免費獲得，或放棄整批角色取得額外10水晶。一般與菁英使用此流程；低階級自動略過角色項目，無階級自動完成。BOSS 由正式 UI 結算後返回首頁，不開領獎視窗。
4. 金錢確認與角色領取（空池則確認）全部完成後入口自動關閉，仍可查看戰鬥結果／統計，再返回地圖。

一般／菁英待領取期間不能移動、再次開戰或開始下一局；BOSS 勝利確認後直接返回首頁。
同伴彈窗點外側或 Escape 返回戰利品入口並保留選項；金錢彈窗關閉視為已確認。入口本身不可略過，也不提供返回戰鬥按鈕。角色已領但金錢未確認時仍不能繼續。彈窗細節見 [介面規範](UI_DESIGN.md)。
重送戰鬥結果、重開視窗或重複領取不會再抽選或發獎。敗北、平手與撤退沒有角色獎勵。

### 放置與空間不足

角色選擇視窗提供「放棄＋10 水晶」：不需先選卡，可放棄整批角色選項並額外取得固定 10 水晶，滿隊也可使用。放棄後不能再領取角色，也不能再次取得這筆補償；以本場 token 驗證。補償不乘戰利品衰減倍率、不取代原戰鬥金錢，原水晶項目仍需確認。只有實際有角色選項時提供；空池與低／無階級零選項不發補償。失敗保留選項與資源，可重試。

- 優先找儲存隊伍的連續空位，再找出戰隊伍。
- 領取不自動合成、不覆蓋既有角色。
- 隊伍已滿仍顯示三個選項，整張角色卡仍可按。
- 放不下時顯示警告，要求先按「整備隊伍」販賣、搬移或手動合成；原選項與待領狀態完整保留。
- 整備在獎勵彈窗上方開啟；關閉整備後繼續領取同一批選項。
- 沒有任何可抽角色時明示原因，提供「繼續旅程」確認空獎勵，不替換示範角色。

## 4. 拖曳與手動合成

點擊角色僅查看資料。整備與商店兩個分頁的自有隊伍都適用下表：

| 拖曳來源與目的地 | 放開後的行為 |
|---|---|
| 自有角色 → 合法空位 | 搬移 |
| 自有角色 → 自己原格 | 不變 |
| 自有角色 → 相同 `id`、相同星等，且低於六星的另一實例 | 合成升一星 |
| 自有角色 → 其他角色，包括不同星等或兩隻六星 | 嘗試交換，必要時將鄰角挪到空間；整組放不下則維持原狀 |
| 自有角色 → 頂部賣出區 | 出售；整備與商店角色分頁可使用 |
| 商店商品 → 自有隊伍合法空位 | 購買 |
| 商店商品 → 已有角色 | 空間不合法，不會購買後直接合成 |
| 商店商品 → 賣出區 | 拒絕 |

合成不另彈確認視窗；正式遊戲使用拖曳落點與合成高亮，不顯示常駐拖曳說明。

多格卡片的落點以拖曳後卡片左緣對齊十格座標，不以游標下整張卡片的起始格代替。例如佔 1～3 格可向右一格放在 2～4 格，原本自身佔位的 null 不視為另一角色；拖曳中以落點框標示實際覆蓋範圍。落在另一角色內部格位時，按完整佔位找出對象；符合合成條件仍優先合成並保留該對象的起始格。

空位搬移優先使用拖入角色的新起始格；放到另一角色卡則交換完整區塊。同隊不同寬度交換時會調整新起始格，例如 `A[12] B[345]` → `B[123] A[45]`，反向亦同，不強迫 A 留在 B 原本的第 3 格。跨隊被交換角色優先移到來源原起始格；若尺寸不合，其他角色可在各自隊伍內挪到空間。暫定保留其他角色的相對順序，優先最少挪動角色，再選總挪動距離較短的配置；不額外把鄰角跨隊搬走。先規劃兩隊完整佔位、驗證後才一次提交，無解或超界時兩隊、金幣、庫存與技能保持原狀。商品購買仍需合法連續空位，不自動擠開或合成角色。

放置優先使用指定起始格；若寬度碰到邊界或固定該格無法排列其餘角色，會由近到遠尋找可容納的位置，落點框與正式提交使用同一份規劃。例如從儲存隊伍向出戰隊伍第 10 格拖入三格角色，可向左貼齊為 8～10 格。跨隊優先交換；若對象放不回來源隊伍，會再嘗試保留對象於目的隊伍、將鄰角推向空格，以插入拖入角色。無完整合法配置時仍全部不提交；購買不採此自動插入規則。

### 合成結果

- 保留被拖到者的 `instanceId`、隊伍與位置，消耗拖過去的角色。
- 每次合成只升一星，最高六星；角色佔位不變，允許跨出戰／儲存隊伍合成。
- 完整繼承雙方全部法則，包含相同 ID 的重複份數；沒有角色法則份數上限。
- 以角色庫快照重新計算「目標星等能力 → 全部法則加成 → 既有能力上下限」，不相加兩隻角色的基礎能力，也不重複套用舊加成。
- 合成後重新檢查技能裝備條件，不符合就卸下，不自動換另一技能。
- 合成免費；購買、領獎與一般開關視窗都不觸發合成。

一星起算，升到二至六星分別需要 2／4／8／16／32 隻一星副本。
這是總投入數量，並非必須同時持有的數量。

## 5. 商店與法則裝備

### 角色分頁

固定由上而下顯示商品、儲存、出戰三排，各十格。角色商品允許重複抽選，商品數不超過
`shopCount`，合計佔位不超過十格。金幣或連續空位不足不成交。
正式商店只以拖商品到隊伍空位購買，點擊商品只查看資料，不提供額外購買按鈕。
商店不提供極式裝備欄，請到整備設定。

### 法則分頁

1. 先顯示商品的永久屬性、被動說明與售價，沒有選角色時停用購買。
2. 玩家將自有角色拖到「法則裝備對象」，不提供點擊後指定的按鈕。
3. 此欄是選定對象，角色仍留在原隊伍與位置，不占額外格位。
4. 點擊整張法則卡直接扣款、消耗商品並附加法則，不另跳確認。
5. 對象維持選取，可連續購買；搬移以 `instanceId` 追蹤，賣掉對象即清除。重開商店需重新選擇。
6. 若選定對象被拖去合成，購買對象會跟隨合成後保留的角色。

法則商品每次固定抽選 4 個，獨立於角色商品與 `shopCount`，不受十格佔位限制；沒有可抽法則時顯示空狀態。正式商店左右各上下堆疊兩張，中央預留三格寬的裝備角色區，一／二／三格卡片依佔格等比置中。法則列高度與出售區加角色商品石板列一致；工坊維持原單行排列；窄版可橫向捲動；卡內顯示敘述，不另列被動標示。
法則沒有 SR／SSR／UR，仍依自己的 `shopWeight` 直接抽選。

### 法則定義與堆疊

| 項目 | 規則 |
|---|---|
| 售價 `shopPrice` | 0～1000000 整數，預設 50；0 表示免費 |
| 出現權重 `shopWeight` | 0～1000000 整數，預設 100；0 排除商店 |
| 法則庫 | 最多 100 種定義，ID 唯一 |
| 角色附掛 | 保存完整快照，可重複同一 ID，可持有超過 100 份 |
| 永久屬性 | 每份相加後套用既有能力上下限 |
| 被動 | 11 種戰鬥事件已觸發執行；6 種旅程事件僅保存設定、尚未支援；結算見 README「戰鬥法則被動」 |

既有敵隊法則也是快照；修改法則庫不會即時改寫已配置的內容。
局內尚無直接移除或轉移法則的操作；整隻角色出售會一併失去法則。

### 販賣與庫存

賣價為 `floor(角色 shopPrice × sellPercent / 100)`，預設返還一半。
星等與法則不增加賣價。售出空位不自動補貨，各店在此次停留期間保存庫存；關閉視窗後店家事件消耗，不能再次購物。

## 6. 回響等級與兩階段角色抽選

商店角色與戰利品共用 `EchoLevels.pick`：

1. 先以本級的 SR／SSR／UR 權重抽階級。
2. 再以該階級角色的 `shopWeight` 抽角色。

階級或角色權重為 0 都不出現。某階級沒有可用角色時，暫時排除該階級，其餘可用階級按原權重重新計算比例。
角色數量或階級內總權重不直接改變第一階段機率。

例如階級 SR:UR = 1:1，即使 SR 有一百種、UR 只有一種，在兩階級皆可用時仍各 50%；
同階級角色 A:B = 1:3，則該階級抽中後，A／B 的條件機率為 25%／75%。

| 用途 | 候選空間與重複規則 |
|---|---|
| 商店 | 排除目前商品陣列放不下的角色；可重複抽同角色 |
| 三選一 | 只排除角色本身超過十格，不依自有隊伍剩餘空間篩選；可用角色足夠時不重複 |

三選一每抽一隻先移出本批候選，再依剩餘候選重新作兩階段抽選。
可用候選耗盡時才重開候選池，補滿三個選項；不為湊不同角色而放行權重 0。
商店顯示的是設定比例，某階級缺角、佔位或三選一去重都可能改變當次實際比例。

### 編輯表與營地

- 分頁入口：`editor.html#echo`。可設定連續 1～100 級，每級三個權重為 0～1000000 整數，至少一項大於 0。
- 新旅程從等級 1 開始，最高為表格最後一級。
- 每個營地抵達時自動免費提升一級並消耗；滿級後也自動完成，可直接繼續前進。
- 升級只影響後續新抽選，不改動已生成的商店或待領戰利品。
- 工坊抵達營地也自動提升該次整備預覽的回響等級；重置探索回到一級。

以下為可調整的平衡初值，並非不可變規則：

| 2 | 80 | 20 | 0 |
| 3 | 60 | 35 | 5 |
| 4 | 40 | 45 | 15 |

## 7. 付費重骰

「重骰全部商品」同時替換該店角色與法則商品，包括已售空位；兩分頁共用一次費用。
使用當前回響等級抽角色，保留自有隊伍、角色、法則與裝備對象，不觸發合成。

```text
本次費用 = shopRerollBase + 該店成功重骰次數 × shopRerollIncrement
```

| Config | 預設 | 範圍 |
|---|---:|---|
| `shopRerollBase` | 20 | 0～1000000 整數 |
| `shopRerollIncrement` | 10 | 0～1000000 整數 |

預設費用依序為 20／30／40…，每間店在停留期間各自累加，離店即消耗商店事件；新旅程或重置探索歸零。
先產生完整的兩類新商品，再一起提交庫存、扣款與次數。
金幣不足、抽取失敗或兩類都沒有商品時，保留原金幣、庫存與次數。

## 8. 資料、相容與驗證

| 已儲存編輯資料 | 格式／讀取規則 |
|---|---|
| `minimajo.echo.v1` | `{version:1,levels:[{SR,SSR,UR},...]}`；等級為陣列索引加一 |

缺少、型別錯誤或超界欄位由 `js/saved-data.js` 逐欄補合法預設，合法 0 保留；讀取不覆寫原始資料。
法則缺少價格／權重補 50／100；重骰缺少費用補 20／10。
回響表缺少、空白或無法辨識時補預設六級；超過一百級只讀前一百級並記錄。
單欄錯誤依對應預設級修復，超過預設六級者使用第六級預設。
單級全 0 時只將 SR 補為 100 並記錄，以恢復可抽選的設定。
版本標記不作為清空或拒絕可讀資料的理由，表單儲存仍嚴格驗證。

隊伍、金幣、待領獎勵、回響當前等級、商品庫存及各店重骰次數都不是編輯存檔，不包含在完整備份中。

主要驗證：`expedition`、`expedition-ui`、`journey`、`journey-ui`、`journey-reward-ui`、
`echo-levels`、`echo-editor`、`laws`、`saved-data`、`editor-backup`、`config` 測試。
