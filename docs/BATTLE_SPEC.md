# 戰鬥規格：敵方極式與陣營事件

2026-11-07 已實作敵隊指定極式、菁英／BOSS 自動施放、敵方圓框及 playerSkill 同陣營限制。其他戰鬥規則沿用 [操作與戰鬥規則](README.md)，旅程與養成沿用 [PROGRESSION_SPEC](PROGRESSION_SPEC.md)。

## 1. 哪些旅程戰鬥啟用敵方極式

| 旅程戰鬥 | 我方極式 | 敵方極式 |
|---|---|---|
| 一般 normal | 沿用裝備及手動／自動設定 | 關閉，不施放 |
| 菁英 elite | 沿用裝備及手動／自動設定 | 啟用，自動施放 |
| 終點 BOSS（goal／boss） | 沿用裝備及手動／自動設定 | 啟用，自動施放 |

敵方與我方分別持有自己的極式、冷卻及就緒狀態。敵方自動模式不受玩家切換我方手動／自動影響；玩家不能代替敵方手動施放。旅程依節點分類決定敵方極式。工坊「隊伍與試打」可獨立指定預覽用敵方極式，不修改敵隊資料；敵隊強度測試既有雙方關閉極式的規則維持不變。

## 2. 自動施放與結算

- 敵方使用與我方自動極式相同的可施放判定，開戰後按技能冷卻充能；時間到且可施放便直接施放，之後重新計算冷卻。
- 尚未開始、暫停、背景分頁、戰鬥結束、隊伍無存活角色或施放者僵直時不施放。冷卻已到但暫時受限時不消耗冷卻，恢復可施放後執行。
- 施放者選取沿用現有規則：本陣營目前陣列中的第一名存活角色。射程、條件、目標與公式以敵方施放者及其陣營為基準，不能套用我方的技能或搜尋方向。
- 成功施放的順序為：消耗冷卻 → 本陣營 playerSkill → 極式效果及連鎖 → 本陣營 allySkillResolved。冷卻中或其他原因拒絕施放，不消耗冷卻、不發送這兩種事件。
- 有效施放但沒有命中／沒有合法效果目標，沿用既有消耗冷卻及結算後事件規則。同一事件鏈每名角色每條固有被動、每份法則每條被動最多一次；死亡／僵直、連鎖中止規則不變。
- 重試同一敵人格仍鎖定原敵隊；敵方極式也須隨該敵隊快照鎖定。每場重建充能狀態，不保留上一場已經走過的冷卻。

## 3. 使用極式的被動只監聽所屬陣營

「我方」是相對於被動持有者的陣營：敵方持有者的我方就是敵隊，不是永遠指玩家。

| 時機 ID | 發送時點 | 可收到事件的持有者 |
|---|---|---|
| playerSkill | 成功施放、扣除冷卻後，極式效果前 | 施放陣營的存活角色／其法則被動 |
| allySkillResolved | 極式效果及其連鎖結算後 | 施放陣營的角色／其法則被動，沿用事件條件及存活／僵直限制 |

- 我方施放只通知我方；敵方施放只通知敵方，手動與自動都適用。
- playerSkill 舊 ID 可沿用；畫面名稱應改為「我方使用極式時」等能表達相對陣營的文字，不能繼續暗示只監聽玩家操作。
- playerSkill 保留原本不使用事件角色範圍／屬性條件的特性，新增的是施放陣營限制；不得用略過範圍條件為理由再次廣播給對手。allySkillResolved 沿用固定 ally 與既有事件角色條件。
- 一般戰鬥敵方沒有極式，因此敵方的這兩種被動不會由任何一方的極式施放事件觸發；敵方不會因我方使用極式就取得一次 playerSkill。
- 這不會停用敵方其他被動。例如我方極式命中敵人仍可能觸發敵人的「被攻擊時」、使其獲得狀態仍可能觸發「獲得狀態時」。這些依各自既有事件規則處理。

## 4. 敵方極式的圓形顯示

- 位置在敵方隊伍左上角「敵方」標牌右側的分隔線區域，形成「敵方標牌 → 極式圓框 → 延伸分隔線」的排列；不是放到我方下方的極式區。
- 已指定敵方極式時顯示圖案與圓框；編隊不符合條件或沒有出戰角色時降低亮度，說明中明示無法施放原因，仍可預覽。這只影響呈現，不繞過施放條件。沒有指定、雙方極式關閉或一般旅程未傳入敵方技能時不顯示。
- 使用既有圓框、技能 imagePath 與冷卻環語彙；空白或缺圖使用現有通用符號，不新增／替換美術素材。敵方圓框尺寸依標牌區可用空間配置，不強制照搬我方大圓框的尺寸。
- 圓框反映敵方自己的冷卻／就緒狀態，跟隨暫停及倍速；不得與倒數、開始／暫停、角色卡或狀態圖示重疊。
- 滑鼠停留顯示敵方極式名稱、冷卻與完整效果說明。鍵盤聚焦亦能查看；手機點按提供相同說明。說明的實際觸發方式不得施放技能或改變冷卻。
- 圓框可作為查看說明的按鈕，但不是玩家可操作的施放按鈕。實際敵方施放一律由自動流程決定。

## 5. 編輯器指定與資料相容

敵隊使用 `skillId: string | null`，預設 null。工坊敵隊表單提供「敵隊極式」下拉選單，由已儲存技能選取；一般分類停用欄位但保留原設定，切回菁英／BOSS 可繼續使用。新隊伍與隨機生成隊伍預設無極式。儲存時驗證引用存在且符合該隊伍星級／法則後的出戰條件，不會另抽替代技能。

舊檔缺少、型別錯誤或 ID 格式無效時逐欄補 null 並列出紀錄；已刪除的極式引用亦補 null，不丟棄敵隊。合法 null 保留。完整備份與編輯器儲存保留此欄位。發布建置允許舊檔缺少此可選欄位並列出補值，但不修改固定 JSON；其他原有發布驗證維持。使用者須自行指定技能，沒有自動替現有敵隊配極式。

旅程快照使用 `enemySkill` 傳送獨立的完整技能，`skills` 仍只含我方已裝備技能。一般敵隊、未指定或不符合條件時不施放；引擎依存活編隊重判條件，停用後不另選其他技能。試煉及工坊既有呼叫未傳入 enemySkill 時維持無敵方極式；強度測試維持雙方關閉。公開歷史勝利隊伍會攜帶當時裝備的完整極式，使用相同自動施放規則，並隨節點鎖定；後端與連接狀態見 [PLAYER_TEAMS_SPEC](PLAYER_TEAMS_SPEC.md) 及部署說明。

## 6. 開局裝備與 BOSS 通關

新旅程完成初始出戰編成後，按已儲存技能庫順序，自動裝備第一個符合條件的極式；沒有符合技能則保持未裝備。只有開局自動選取，後續購買、搬移、合成與販賣仍只檢查現有裝備，失效時卸下，不擅自改裝另一技能；玩家仍可在整備手動更換。

擊敗終點 BOSS 後保留 VICTORY 待點擊確認；確認後父頁驗證結果 token、完成一次勝利結算，隨即導向 index.html。終點不再開戰利品視窗或等待返回地圖／開始新旅程；一般與菁英領獎不變。純旅程引擎仍保留結算資料，正式 UI 在通關時離開本局；沒有續玩存檔。敗北仍按既有規則退回前格，終點平手不視為通關、不自動返回首頁。

## 7. 實作驗收

1. 一般敵方不建立可施放極式；菁英／BOSS 使用自己的極式，冷卻到即自動施放，玩家切換我方自動不影響敵方。
2. 雙方各放一次：playerSkill 在效果前、allySkillResolved 在效果後各只通知施放陣營。角色固有被動與重複法則均遵守同一陣營與連鎖限制。
3. 冷卻未到、未開戰、暫停、背景、僵直或結束時不施放／不觸發；有效施放但無目標仍按既有規則處理。
4. 敵方標牌區顯示其技能及冷卻；桌面 hover、鍵盤 focus、手機點按可查看說明，不會施放或重設冷卻。
5. 一般／菁英／BOSS、敗北重試、戰前整備、同角色多實例、十格與多格角色皆驗證；現有純引擎、iframe 與結算測試同步更新。

## 8. 工坊試打與直接戰前調位

「隊伍與試打」的「試打敵方極式」預設無極式，可選已儲存技能；此為本頁暫存預覽設定，不寫入固定 JSON、不改任何敵隊 skillId，重載回預設。變更會重建試打並更新上方 iframe；不符合敵方編隊條件時顯示不符合，不能施放。開戰後鎖定，重新試煉後可改。「啟用我方極式」只控制我方，敵方指定技能仍可預覽與自動施放。

戰鬥開始前可以直接拖曳角色調位，不必先開整備。旅程只允許我方，工坊允許雙方；獨立展示允許我方。沿用共用十格佔位與不同寬度交換的規劃，完整角色搬移、後續佔位仍是 null；保留角色實例、星等與全部法則，不在戰鬥卡上合成或販賣。點擊仍查看詳情，拖曳超過門檻後抑制誤點；支援滑鼠與觸控，放到陣列外取消。拖曳時以原尺寸完整卡片跟隨指標，保留抓取偏移，原位淡化；預覽不攔截操作、不改編隊，取消或結束後立即清除。

旅程由父頁驗證來源 iframe、戰鬥 token、尚未開戰與我方陣營後，一次更新本局 active 及開戰快照；更新失敗保留原隊伍、資源與敵隊，子頁顯示錯誤。更新期間禁止開戰，成功回傳新快照／token。工坊同樣由父頁更新角色、星等與法則位置，再刷新表單及試打；不只移動畫面。調位後沿用技能條件檢查，失效就卸下，不自動改裝。開戰後即使暫停仍禁止拖動。

## 9. 版本與驗證界線

playerSkill 既有 ID 沿用，顯示名稱改為「我方使用極式時」，只通知施放陣營；allySkillResolved 保留。2026-11-07 核對固定 JSON，沒有 allySkillResolved 設定，不因此刪除此時機。發布戰鬥規則版本提升為 2。

自動測試包括雙方施放、角色／法則事件、冷卻／僵直、同陣營、可選欄位補值與引用修復、開局選技能與旅程 payload。瀏覽器腳本 tests/browser/enemy-ultimate.cjs 使用測試專用固定 JSON，驗證編輯器存回／重載、真實 iframe 敵方自動施放、暫停、三種尺寸的圖案與說明，以及 BOSS 結果訊息返回首頁。BOSS 結果以測試訊息建立，未完整手動遊玩自然旅程，也未部署此版。
