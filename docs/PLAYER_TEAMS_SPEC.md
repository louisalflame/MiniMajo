# 勝利隊伍紀錄與歷史敵隊

2026-11-07 使用者確認。本規格適用公開旅程；工坊、獨立戰鬥展示不讀寫線上紀錄。

## 記錄

- 一般、菁英、BOSS 都在實際開戰時保留最終出戰快照，只有有效勝利結算才提交；敗北與平手不提交。
- 適配等級使用開戰當時的隱藏 playerLevel，勝利加級前的值。保留十格原始站位、多格佔位 null、角色 instanceId、星等、能力、固有被動、全部法則與已裝備極式。
- 使用開戰編成，不採用戰場移位、殘血、戰鬥狀態或戰後獎勵；死亡角色仍包含在隊伍中。戰前調位與整備更新後才建立實際開戰快照。
- 同旅程、同適配等級保留一份勝利紀錄，以旅程隨機ID＋等級＋相容版本唯一識別。網路重送與重複結算不產生額外紀錄。
- 無登入、暱稱、排行榜或戰鬥真偽驗證。保留格式／大小驗證，避免無法還原的資料進入紀錄池。

## 選敵

- 一般戰鬥保持編輯器敵隊，不查詢歷史資料。
- 菁英與BOSS共用歷史勝利池，同級優先；否則在上下2級內選差距最小等級，同差距取較低等級，再於該等級隨機抽一份。
- 歷史玩家BOSS也依適配等級選取；原本的編輯器BOSS仍保持既有不適配、按權重抽選規則。
- 有符合紀錄即使用，不額外放大能力；沒有資料、服務失敗、逾時或紀錄不可還原時回到原編輯器抽選。
- 排除同一旅程，先讀取對手再提交本次勝利。其他新旅程可遇到同一瀏覽器先前留下的隊伍。
- 第一次進入節點後鎖定敵隊及極式；戰前整備、拖曳調位、敗北重試不重抽。每場滿血、清空狀態，敵方極式依既有菁英／BOSS規則自動施放。

## 版本與失敗

- poolVersion 由戰鬥規則版本及平衡相關資料計算。純圖片／敘述／介面調整不清空匹配池；戰鬥數值、效果與規則改變後只配對相容版本，舊紀錄保留。
- 讀取最多等待1.8秒；逾時使用原敵隊並鎖定備援結果，不阻擋重試。上傳不阻擋遊戲與獎勵。
- 同分頁 sessionStorage 保存最多10筆待傳勝利紀錄，供同網站首頁／下一旅程或恢復連線時重試；這不是旅程存檔。儲存空間不足、分頁關閉或持續離線可能丟失未傳紀錄。
- BOSS勝利仍返回首頁，首頁會補送待傳紀錄；短資料使用 keepalive，較大資料依待傳佇列補送。伺服器以唯一鍵去重。

## 後端

Pages Functions 的 /api/player-teams 提供GET配對及POST勝利紀錄，/api/health提供連線檢查。D1綁定名稱DB，預覽與正式環境分庫。靜態資源不經Functions。單筆請求最多512 KiB，資料庫保存完整可還原快照及enabled停用欄位，不開放公用管理寫入介面。

只有程式與本機測試完成不代表已連上正式D1。建立資料庫、執行migration、綁定及重新部署後，需用兩個獨立旅程驗證真實上傳與匹配。
